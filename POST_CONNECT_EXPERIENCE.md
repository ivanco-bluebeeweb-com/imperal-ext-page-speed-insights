# Page Speed Insights — что видит и чем управляет пользователь после подключения

## 1. Целевой пользователь
Веб-разработчик/маркетолог, отвечающий за скорость загрузки сайта (Core Web Vitals) —
критично для SEO-ранжирования и конверсии.

## 2. Момент истины после подключения
Сразу можно вызвать `analyze_page` по любому URL и получить реальную оценку Core Web
Vitals (LCP, CLS, INP) и Lighthouse-скор — как для мобильной, так и для десктоп-версии.

## 3. Что пользователь видит
- Оценку производительности страницы (Performance score 0-100) — `analyze_page`.
- Core Web Vitals из реальных пользовательских данных (CrUX) и из лабораторного теста —
  `get_field_data`, `get_lab_data`.
- Конкретные рекомендации по улучшению (какой ресурс блокирует рендер, что не
  оптимизировано) — `get_optimization_opportunities`.
- Историю замеров той же страницы во времени (если сохраняется) — `list_analysis_history`.
- Сравнение мобильной и десктоп-версии одной страницы — `analyze_page` с обоими strategy.

## 4. Чем пользователь может управлять
- Запускать анализ по любому URL (не только своему домену — можно и конкурента) —
  `analyze_page`.
- Ставить URL на регулярный мониторинг скорости — `schedule_periodic_analysis`.
- Экспортировать отчёт с рекомендациями для передачи разработчику — `export_report`.

## 5. "Вау"-момент для демо потенциальному клиенту
"Смотри — говорю Webbee: 'почему моя главная страница медленно грузится на мобильных?'.
Она через `analyze_page` находит конкретную причину (например, не оптимизированное
изображение) — с точным указанием, что чинить, а не общими словами 'сайт медленный'."

## 6. Что делает это "заточенным под него"
`analyze_page` тестирует РЕАЛЬНУЮ, живую версию именно его сайта прямо сейчас — не
кэшированный отчёт, а честный live-замер на момент запроса.
