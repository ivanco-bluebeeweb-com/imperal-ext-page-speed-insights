# Page Speed Insights — идеальный первый запуск

Источник: `ONBOARDING_FIRST_LAUNCH_STANDARD.md`. Целевой пользователь: веб-разработчик/
маркетолог, отвечающий за Core Web Vitals сайта.

## 1. Credential type
API key (Google API key, одно поле — самый простой класс в портфеле, без OAuth-
сложности, т.к. PageSpeed API работает по обычному API key, не user-delegated OAuth).

## 2. Идеальный флоу
1. **Первое открытие** — `Empty` со ссылкой на Google Cloud Console (создание API key
   + включение PageSpeed Insights API) — короткая, понятная инструкция, т.к. этот шаг
   неочевиден для не-технического маркетолога.
2. **Форма** — api_key (password-type) с лейблом.
3. **После успеха** — форма проверки URL должна быть ПЕРВЫМ, что видно в центре — ввод
   адреса сайта + кнопка "Проверить скорость" — максимально прямой путь к ценности, без
   промежуточных экранов.
4. **Connected sites cross-app** — если у пользователя уже есть сайты в Sites Registry/
   WordPress Hub — предзаполненный список для быстрого выбора вместо ручного ввода URL.
5. **Ошибка "API not enabled"** — Google требует явного включения PageSpeed Insights
   API в проекте — конкретное сообщение с прямой ссылкой на включение, не общая 403.
